# 1. Record Architecture Decisions

Date: 2026-10-20

## Status
Accepted

## Context
We need to record architectural decisions made on project TaskFlow so that teammates, future contributors, and evaluators can understand the architectural context, tradeoffs, and rationale.

## Decision
We will use Architecture Decision Records (ADRs) as described by Michael Nygard. We will store them in markdown format in `docs/adr/` with numbered filenames.

## Consequences
- Important technical decisions and tradeoffs will be documented in version control alongside code.
- Developers must maintain and update ADRs whenever significant architectural decisions are made.
